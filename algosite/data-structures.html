Arrays

An array is a fixed-size, ordered collection of elements stored in contiguous memory. Because each element sits right next to the last one, the computer can jump directly to any position in one step using a simple math formula: address = base + index × element_size. This makes reading blazing fast but inserting or deleting in the middle expensive, because everything after that position must shift.

Think of it like… numbered theatre seats in a row. You can walk straight to seat 42 without checking every row first. But if a new seat is added at position 10, every person from seat 10 onward must move one spot.

Common Operations

OperationTimeNotes
Access by indexO(1)Direct memory address calculation
Search (unsorted)O(n)Must scan each element
Append to endO(1) amortizedDynamic arrays grow by doubling
Insert in middleO(n)Must shift elements right
Delete in middleO(n)Must shift elements left

Code Examples

Python 
# Python lists are dynamic arrays
arr = [10, 20, 30, 40, 50]

# O(1) — access by index
print(arr[2])         # 30

# O(1) amortized — append to end
arr.append(60)        # [10, 20, 30, 40, 50, 60]

# O(n) — insert in the middle (shifts everything right)
arr.insert(1, 15)     # [10, 15, 20, 30, 40, 50, 60]

# O(n) — remove by value
arr.remove(15)        # [10, 20, 30, 40, 50, 60]

# O(n) — search
idx = arr.index(30)   # 2

# O(k) — slice (creates a copy of k elements)
sub = arr[1:4]        # [20, 30, 40]

print(f"Length: {len(arr)}")          # 6
print(f"Found 30 at index: {idx}")    # Found 30 at index: 2
TypeScript

// O(1) — access by index

// O(k) — slice without mutating

console.log(`Length: ${arr.length}`);       // 6
console.log(`Found 30 at index: ${idx}`);
Where you see this in real software: Image pixels, audio samples, database rows in a result set, and any list where you need fast indexed access — like the frames of a video or the cells of a spreadsheet.

Linked Lists

A linked list is a chain of nodes scattered anywhere in memory. Each node stores its value and a pointer to the next node. Because nodes are connected by pointers rather than physical position, inserting or removing at the front is instant — just update a pointer. But finding the 10th element means walking the chain from the beginning.

Think of it like… a treasure hunt with clues. Each clue tells you where the next one is. To reach clue 8, you must follow clues 1 through 7 in order — there's no shortcut. But adding a new first clue just means pointing it at the old first clue, which is instant.

Common Operations

OperationTimeNotes
Access by indexO(n)Must traverse from head
Prepend (insert at head)O(1)Just update the head pointer
Append (insert at tail)O(n) or O(1)*O(1) if tail pointer is kept
Delete at headO(1)Just update the head pointer
Delete by valueO(n)Must find the node first
SearchO(n)Sequential scan from head

Code Examples

Python 
class Node:
    def __init__(self, val):
        self.val = val
        self.next = None

class LinkedList:
    def __init__(self):
        self.head = None

    def prepend(self, val):       # O(1)
        node = Node(val)
        node.next = self.head
        self.head = node

    def append(self, val):        # O(n) — walks to the end
        node = Node(val)
        if not self.head:
            self.head = node
            return
        cur = self.head
        while cur.next:
            cur = cur.next
        cur.next = node

    def delete(self, val):        # O(n)
        if self.head and self.head.val == val:
            self.head = self.head.next
            return
        cur = self.head
        while cur and cur.next:
            if cur.next.val == val:
                cur.next = cur.next.next
                return
            cur = cur.next

    def to_list(self):            # O(n)
        result, cur = [], self.head
        while cur:
            result.append(cur.val)
            cur = cur.next
        return result

ll = LinkedList()
ll.append(1); ll.append(2); ll.append(3)
ll.prepend(0)
print(ll.to_list())   # [0, 1, 2, 3]
ll.delete(2)
print(ll.to_list())   # [0, 1, 3]
TypeScript 
class ListNode<T> {
  constructor(public val: T, public next: ListNode<T> | null = null) {}
}

class LinkedList<T> {
  private head: ListNode<T> | null = null;

  prepend(val: T): void {          // O(1)
    this.head = new ListNode(val, this.head);
  }

  append(val: T): void {           // O(n)
    const node = new ListNode(val);
    if (!this.head) { this.head = node; return; }
    let cur = this.head;
    while (cur.next) cur = cur.next;
    cur.next = node;
  }

  delete(val: T): void {           // O(n)
    if (this.head?.val === val) { this.head = this.head.next; return; }
    let cur = this.head;
    while (cur?.next) {
      if (cur.next.val === val) { cur.next = cur.next.next; return; }
      cur = cur.next;
    }
  }

  toArray(): T[] {
    const result: T[] = [];
    let cur = this.head;
    while (cur) { result.push(cur.val); cur = cur.next; }
    return result;
  }
}

const ll = new LinkedList<number>();
ll.append(1); ll.append(2); ll.append(3); ll.prepend(0);
console.log(ll.toArray()); // [0, 1, 2, 3]
ll.delete(2);
console.log(ll.toArray()); // [0, 1, 3]
Where you see this in real software: Undo/redo history chains, music playlists, browser tab history, and as the internal building block for stacks, queues, and LRU caches.

Stacks

A stack is a Last In, First Out (LIFO) structure. You can only interact with the top element. Pushing adds to the top; popping removes from the top. This constraint is exactly what makes stacks useful — the newest item is always the easiest to find and reverse.

Think of it like… a stack of plates in a cafeteria. You always take the plate from the top — which is the one most recently placed there. You can't grab a plate from the middle without moving the ones above it first.

Common Operations

OperationTimeNotes
Push (add to top)O(1)Append to end of underlying array
Pop (remove from top)O(1)Remove last element of underlying array
Peek (read top without removing)O(1)Access last element by index
isEmptyO(1)Check if size is zero

Code Examples

Python 
# Python list works perfectly as a stack
stack = []

stack.append("page1")   # push — O(1)
stack.append("page2")   # push — O(1)
stack.append("page3")   # push — O(1)

print(stack[-1])        # peek top — O(1) → "page3"
print(stack.pop())      # pop — O(1)      → "page3"
print(stack.pop())      # pop — O(1)      → "page2"
print(stack)            # ["page1"]

# Real-world: undo history in a text editor
class UndoHistory:
    def __init__(self):
        self._stack = []

    def do_action(self, action):
        self._stack.append(action)

    def undo(self):
        if self._stack:
            return self._stack.pop()   # most recent action reversed first
        return None

history = UndoHistory()
history.do_action("type 'Hello'")
history.do_action("bold text")
history.do_action("change font")

print(history.undo())   # "change font"  — last action undone first
print(history.undo())   # "bold text"
TypeScript 
class Stack<T> {
  private items: T[] = [];

  push(item: T): void       { this.items.push(item); }        // O(1)
  pop(): T | undefined      { return this.items.pop(); }      // O(1)
  peek(): T | undefined     { return this.items[this.items.length - 1]; } // O(1)
  isEmpty(): boolean        { return this.items.length === 0; }
  size(): number            { return this.items.length; }
}

// Browser history simulation
const browserHistory = new Stack<string>();
browserHistory.push("home");
browserHistory.push("about");
browserHistory.push("contact");

console.log(browserHistory.peek()); // "contact"
browserHistory.pop();               // go back
console.log(browserHistory.peek()); // "about"

// Checking balanced parentheses — a classic stack problem
function isBalanced(s: string): boolean {
  const stack = new Stack<string>();
  const pairs: Record<string, string> = { ')': '(', ']': '[', '}': '{' };
  for (const ch of s) {
    if ("([{".includes(ch)) stack.push(ch);
    else if (ch in pairs) {
      if (stack.pop() !== pairs[ch]) return false;
    }
  }
  return stack.isEmpty();
}

console.log(isBalanced("([{}])"));  // true
console.log(isBalanced("([)]"));    // false
Where you see this in real software: Browser back button, undo in every editor, function call stack (how programs track which function called which), expression parsing, and syntax highlighting.

Queues

A queue is a First In, First Out (FIFO) structure. Items join at the back (enqueue) and leave from the front (dequeue). The item waiting longest is always served next. This fairness property makes queues the right choice for any system where order matters.

Think of it like… a line at a coffee shop. The first person in line is served first. New customers join at the back. No jumping the queue — everyone waits their turn.

Common Operations

OperationTimeNotes
Enqueue (add to back)O(1)Append to end
Dequeue (remove from front)O(1)Use deque for true O(1); array shift is O(n)
Peek frontO(1)Read without removing
isEmptyO(1)Check if size is zero

Code Examples

Python 
from collections import deque

# deque gives true O(1) operations on both ends
queue = deque()

queue.append("task1")    # enqueue — O(1)
queue.append("task2")    # enqueue — O(1)
queue.append("task3")    # enqueue — O(1)

print(queue[0])          # peek front — "task1"
print(queue.popleft())   # dequeue — O(1) → "task1"
print(queue.popleft())   # dequeue — O(1) → "task2"
print(list(queue))       # ["task3"]

# Real-world: print job queue
class PrintQueue:
    def __init__(self):
        self._queue = deque()

    def add_job(self, job):
        self._queue.append(job)
        print(f"Queued: {job}")

    def print_next(self):
        if self._queue:
            job = self._queue.popleft()
            print(f"Printing: {job}")
        else:
            print("Queue is empty")

pq = PrintQueue()
pq.add_job("report.pdf")
pq.add_job("invoice.pdf")
pq.print_next()   # Printing: report.pdf (first in, first out)
pq.print_next()   # Printing: invoice.pdf
TypeScript 
// Queue with O(1) enqueue and dequeue using a linked list internally
class QueueNode<T> {
  constructor(public val: T, public next: QueueNode<T> | null = null) {}
}

class Queue<T> {
  private head: QueueNode<T> | null = null;
  private tail: QueueNode<T> | null = null;
  private _size = 0;

  enqueue(val: T): void {             // O(1)
    const node = new QueueNode(val);
    if (this.tail) this.tail.next = node;
    this.tail = node;
    if (!this.head) this.head = node;
    this._size++;
  }

  dequeue(): T | undefined {          // O(1)
    if (!this.head) return undefined;
    const val = this.head.val;
    this.head = this.head.next;
    if (!this.head) this.tail = null;
    this._size--;
    return val;
  }

  peek(): T | undefined { return this.head?.val; }
  isEmpty(): boolean    { return this._size === 0; }
  size(): number        { return this._size; }
}

const q = new Queue<string>();
q.enqueue("task1"); q.enqueue("task2"); q.enqueue("task3");
console.log(q.dequeue()); // "task1"
console.log(q.dequeue()); // "task2"
console.log(q.size());    // 1
Where you see this in real software: Print queues, web server request handling, message brokers (Kafka, RabbitMQ), keyboard input buffers, and as the core data structure behind BFS graph traversal.

Deques (Double-Ended Queues)

A deque (pronounced "deck") lets you add and remove elements from both the front and the back in O(1) time. It behaves as a stack when you use only one end, and as a queue when you use back-in / front-out. This flexibility makes it the right tool for sliding-window problems and palindrome detection.

Think of it like… a tube of sweets open at both ends. You can pop a candy from either end instantly. A normal queue is a tube open at both ends but you're only allowed to insert from one side. A deque removes that restriction.

Common Operations

OperationTimeNotes
Push front / Push backO(1)Both ends equally fast
Pop front / Pop backO(1)Both ends equally fast
Peek front / Peek backO(1)—

Code Examples

Python 
from collections import deque

dq = deque([3, 4, 5])

dq.appendleft(2)   # add to front — O(1)
dq.appendleft(1)   # add to front — O(1)
dq.append(6)       # add to back  — O(1)

print(list(dq))    # [1, 2, 3, 4, 5, 6]

dq.popleft()       # remove from front — O(1) → 1
dq.pop()           # remove from back  — O(1) → 6

print(list(dq))    # [2, 3, 4, 5]

# Classic use: sliding window maximum
def max_sliding_window(nums, k):
    """Return max of every window of size k in O(n)."""
    dq = deque()      # stores indices, not values
    result = []
    for i, num in enumerate(nums):
        # evict indices that are outside the current window
        while dq and dq[0] < i - k + 1:
            dq.popleft()
        # keep only indices of elements that could be the max
        while dq and nums[dq[-1]] < num:
            dq.pop()
        dq.append(i)
        if i >= k - 1:
            result.append(nums[dq[0]])
    return result

nums = [1, 3, -1, -3, 5, 3, 6, 7]
print(max_sliding_window(nums, k=3))  # [3, 3, 5, 5, 6, 7]
TypeScript 
// Deque backed by a doubly-linked list for true O(1) on both ends
class DequeNode<T> {
  constructor(
    public val: T,
    public prev: DequeNode<T> | null = null,
    public next: DequeNode<T> | null = null
  ) {}
}

class Deque<T> {
  private head: DequeNode<T> | null = null;
  private tail: DequeNode<T> | null = null;
  private _size = 0;

  pushFront(val: T): void {          // O(1)
    const node = new DequeNode(val, null, this.head);
    if (this.head) this.head.prev = node;
    this.head = node;
    if (!this.tail) this.tail = node;
    this._size++;
  }

  pushBack(val: T): void {           // O(1)
    const node = new DequeNode(val, this.tail, null);
    if (this.tail) this.tail.next = node;
    this.tail = node;
    if (!this.head) this.head = node;
    this._size++;
  }

  popFront(): T | undefined {        // O(1)
    if (!this.head) return undefined;
    const val = this.head.val;
    this.head = this.head.next;
    if (this.head) this.head.prev = null; else this.tail = null;
    this._size--;
    return val;
  }

  popBack(): T | undefined {         // O(1)
    if (!this.tail) return undefined;
    const val = this.tail.val;
    this.tail = this.tail.prev;
    if (this.tail) this.tail.next = null; else this.head = null;
    this._size--;
    return val;
  }

  peekFront(): T | undefined { return this.head?.val; }
  peekBack(): T | undefined  { return this.tail?.val; }
  isEmpty(): boolean         { return this._size === 0; }
  size(): number             { return this._size; }
}

// Palindrome check using a deque
function isPalindrome(s: string): boolean {
  const dq = new Deque<string>();
  for (const ch of s) dq.pushBack(ch);
  while (dq.size() > 1) {
    if (dq.popFront() !== dq.popBack()) return false;
  }
  return true;
}

console.log(isPalindrome("racecar")); // true
console.log(isPalindrome("hello"));   // false
Where you see this in real software: Sliding window algorithms, undo/redo with both forward and backward navigation, work-stealing schedulers (worker threads steal tasks from the back of other workers' deques), and browser tab history with forward/back buttons.

Hashmaps

A hashmap (also called a dictionary or hash table) stores key-value pairs and retrieves values in O(1) average time. A hash function converts the key into an index (a "bucket" number), and the value is stored there. Because the bucket is computed — not searched — lookup is near-instant regardless of how many entries are in the map.

Think of it like… a dictionary book. When you look up "ephemeral," you don't read every page from A to Z. You jump straight to the E section. The hash function is the rule that tells you which section to open.

Common Operations

OperationAverage TimeWorst Case
Insert / UpdateO(1)O(n) — many hash collisions
Lookup by keyO(1)O(n) — many hash collisions
Delete by keyO(1)O(n) — many hash collisions
Iterate all entriesO(n)O(n)

Code Examples

Python 
# Python's built-in dict is a hashmap
phone_book = {}

# Insert — O(1) average
phone_book["Alice"] = "555-1234"
phone_book["Bob"]   = "555-5678"
phone_book["Carol"] = "555-9012"

# Lookup — O(1) average
print(phone_book["Alice"])           # "555-1234"
print(phone_book.get("Dave", "N/A")) # "N/A" (safe — no KeyError)

# Delete — O(1) average
del phone_book["Bob"]

# Membership check — O(1) average
print("Carol" in phone_book)         # True

# Iterate — O(n)
for name, number in phone_book.items():
    print(f"{name}: {number}")

# Common pattern: count character frequencies
text = "hello world"
freq = {}
for ch in text:
    freq[ch] = freq.get(ch, 0) + 1
print(freq)
# {'h': 1, 'e': 1, 'l': 3, 'o': 2, ' ': 1, 'w': 1, 'r': 1, 'd': 1}
TypeScript 
// Use Map for key-value storage (better than plain objects for this purpose)
const phoneBook = new Map<string, string>();

// Insert — O(1) average
phoneBook.set("Alice", "555-1234");
phoneBook.set("Bob",   "555-5678");
phoneBook.set("Carol", "555-9012");

// Lookup — O(1) average
console.log(phoneBook.get("Alice"));          // "555-1234"
console.log(phoneBook.get("Dave") ?? "N/A");  // "N/A"

// Delete — O(1) average
phoneBook.delete("Bob");

// Membership check — O(1) average
console.log(phoneBook.has("Carol"));  // true

// Iterate — O(n)
for (const [name, number] of phoneBook) {
  console.log(`${name}: ${number}`);
}

// Count character frequencies
const text = "hello world";
const freq = new Map<string, number>();
for (const ch of text) {
  freq.set(ch, (freq.get(ch) ?? 0) + 1);
}
console.log(freq.get("l")); // 3
Where you see this in real software: Database indexes, caches (Redis is essentially a hashmap over a network), session storage, URL routing tables, and any feature that needs O(1) lookup — like "has this user already voted?" or "what is the config value for this key?"

Hashsets

A hashset is a hashmap with no values — just keys. It answers one question blazingly fast: "Is this item in the set?" It also automatically prevents duplicates. Internally, a hashset is the same structure as a hashmap; it just ignores the value slot.

Think of it like… a guest list at a club. The bouncer doesn't care what each person "holds" — they just check if the name is on the list or not. Adding the same name twice changes nothing. The check is instant.

Common Operations

OperationAverage TimeNotes
Add itemO(1)Silently ignores duplicates
Check membershipO(1)The primary use case
Remove itemO(1)—
Union / Intersection / DifferenceO(n)—

Code Examples

Python 
# Python's built-in set is a hashset
visited = set()

visited.add("page1")
visited.add("page2")
visited.add("page1")    # duplicate — silently ignored
print(visited)           # {'page1', 'page2'} — no duplicates

# O(1) membership check
print("page1" in visited)   # True
print("page3" in visited)   # False

# Remove safely
visited.discard("page2")    # no error if missing (unlike .remove())

# Set math
a = {1, 2, 3, 4}
b = {3, 4, 5, 6}
print(a & b)   # intersection: {3, 4}
print(a | b)   # union:        {1, 2, 3, 4, 5, 6}
print(a - b)   # difference:   {1, 2}
print(a ^ b)   # symmetric diff: {1, 2, 5, 6}

# Remove duplicates while preserving sort order
data = [3, 1, 4, 1, 5, 9, 2, 6, 5, 3]
unique = sorted(set(data))
print(unique)   # [1, 2, 3, 4, 5, 6, 9]
TypeScript

visited.add("page1");
visited.add("page2");
visited.add("page1");       // duplicate — ignored
console.log(visited.size);  // 2

// Set operations (no built-in operators in TypeScript — use spread)
const a = new Set([1, 2, 3, 4]);

const union        = new Set([...a, ...b]);                     // {1,2,3,4,5,6}
const difference   = new Set([...a].filter(x => !b.has(x)));  // {1, 2}

const data = [3, 1, 4, 1, 5, 9, 2, 6, 5, 3];

Where you see this in real software: Web crawlers (tracking visited URLs), deduplication pipelines, "already seen" checks in recommendation systems, and efficient lookups when you don't need the values — just whether something exists.

Trees

A tree is a hierarchical structure of nodes connected by edges. There is exactly one root node at the top, and each node can have zero or more children. Nodes with no children are called leaves. Unlike arrays or lists, trees branch — which makes them perfect for representing anything with a parent-child relationship.

Think of it like… a company org chart or a file system. The CEO (root) has direct reports (children). Each direct report has their own team (children). The interns at the bottom have no one reporting to them — they are the leaves.

Key Terms

TermMeaning
RootThe single top node with no parent
LeafA node with no children
HeightLongest path from root to a leaf
DepthDistance from the root to a specific node
SubtreeA node and all its descendants

Code Examples

Python 
class TreeNode:
    def __init__(self, val):
        self.val = val
        self.children = []

    def add_child(self, child):
        self.children.append(child)

# Build a file-system tree
root = TreeNode("root")
docs = TreeNode("Documents")
pics = TreeNode("Pictures")
root.add_child(docs)
root.add_child(pics)
docs.add_child(TreeNode("resume.pdf"))
docs.add_child(TreeNode("notes.txt"))
pics.add_child(TreeNode("vacation.jpg"))

# DFS pre-order traversal (parent before children)
def dfs(node, depth=0):
    print("  " * depth + node.val)
    for child in node.children:
        dfs(child, depth + 1)

dfs(root)
# root
#   Documents
#     resume.pdf
#     notes.txt
#   Pictures
#     vacation.jpg

# BFS level-order traversal (layer by layer)
from collections import deque

def bfs(root):
    queue = deque([root])
    while queue:
        node = queue.popleft()
        print(node.val, end="  ")
        for child in node.children:
            queue.append(child)

bfs(root)   # root  Documents  Pictures  resume.pdf  notes.txt  vacation.jpg

Binary Search Trees (BST)

A binary search tree is a special tree where every node has at most two children (left and right), and it enforces a sorting rule: everything in the left subtree is smaller than the parent, and everything in the right is larger. This rule means searching cuts the remaining possibilities in half with each step — just like binary search on a sorted array, but without needing to shift elements on insert.

Think of it like… a game of "higher or lower?" You pick a number. Your friend says "higher" or "lower." Each answer cuts the remaining possibilities in half. A BST bakes this game into the tree's structure so the computer automatically knows which branch to follow.

Common Operations

OperationAverage (Balanced)Worst Case (Skewed)
SearchO(log n)O(n)
InsertO(log n)O(n)
DeleteO(log n)O(n)
In-order traversal (sorted output)O(n)O(n)

        self.val = val
        self.left = None
        self.right = None

class BST:
    def __init__(self):
        self.root = None

    def insert(self, val):              # O(log n) average
        self.root = self._insert(self.root, val)

    def _insert(self, node, val):
        if not node:
            return BSTNode(val)
        if val < node.val:
            node.left = self._insert(node.left, val)
        elif val > node.val:
            node.right = self._insert(node.right, val)
        # Equal values are ignored (no duplicates)
        return node

    def search(self, val):             # O(log n) average
        node = self.root
        while node:
            if val == node.val:
                return True
            node = node.left if val < node.val else node.right
        return False

    def in_order(self):                # O(n) — returns values in sorted order!
        result = []
        def _walk(node):
            if node:
                _walk(node.left)
                result.append(node.val)
                _walk(node.right)
        _walk(self.root)
        return result

  }

    if (!node) return new BSTNode(val);
    if      (val < node.val) node.left  = this._insert(node.left, val);
    else if (val > node.val) node.right = this._insert(node.right, val);
    return node;
  }

    let cur = this.root;
    while (cur) {
      if (val === cur.val) return true;
      cur = val < cur.val ? cur.left : cur.right;
    }
    return false;
  }

  inOrder(): number[] {                  // O(n) — sorted output
    const result: number[] = [];
    function walk(node: BSTNode | null) {
      if (!node) return;
      walk(node.left);
      result.push(node.val);
      walk(node.right);
    }
    walk(this.root);
    return result;
  }
}

Heaps

A heap is a tree-based structure optimized for priority access. In a min-heap, the smallest element is always at the top (root). In a max-heap, the largest is at the top. Every insert or removal reorganizes the tree to restore this property — which takes O(log n). But peeking at the top is always O(1).

Think of it like… an emergency room triage system. Patients enter in any order, but the most critical patient is always seen first. When a patient is discharged, the next most critical rises to the top automatically. The heap always puts the highest priority item within instant reach.

Peek top (min or max)O(1)Root is always the priority element
Insert (push)O(log n)Add at end, bubble up
Remove top (pop)O(log n)Replace root with last, sift down
Build heap from arrayO(n)More efficient than n inserts

// Min-heap implementation (stores numbers for clarity)
class MinHeap {
  private data: number[] = [];

  push(val: number): void {         // O(log n)
    this.data.push(val);
    this._bubbleUp(this.data.length - 1);
  }

  pop(): number | undefined {       // O(log n)
    if (this.data.length === 0) return undefined;
    const top = this.data[0];
    const last = this.data.pop()!;
    if (this.data.length > 0) {
      this.data[0] = last;
      this._siftDown(0);
    }
    return top;
  }

  peek(): number | undefined { return this.data[0]; } // O(1)
  size(): number { return this.data.length; }

  private _bubbleUp(i: number): void {
    while (i > 0) {
      const parent = Math.floor((i - 1) / 2);
      if (this.data[parent] <= this.data[i]) break;
      [this.data[parent], this.data[i]] = [this.data[i], this.data[parent]];
      i = parent;
    }
  }

  private _siftDown(i: number): void {
    const n = this.data.length;
    while (true) {
      let smallest = i;
      const l = 2 * i + 1, r = 2 * i + 2;
      if (l < n && this.data[l] < this.data[smallest]) smallest = l;
      if (r < n && this.data[r] < this.data[smallest]) smallest = r;
      if (smallest === i) break;
      [this.data[smallest], this.data[i]] = [this.data[i], this.data[smallest]];
      i = smallest;
    }
  }
}

Graphs

A graph is a collection of nodes (vertices) connected by edges. Unlike trees, graphs have no root and can contain cycles. Edges can be undirected (friendship: Alice knows Bob, Bob knows Alice) or directed (Twitter follow: Alice follows Bob, but Bob doesn't follow Alice). Edges can also carry a weight (distance, cost, capacity).

Think of it like… a road map or social network. Cities are nodes. Roads are edges. Some roads are one-way (directed). Some roads have tolls (weighted). Finding the shortest route from A to B is a graph problem. Suggesting "people you may know" is also a graph problem.

from collections import defaultdict, deque

class Graph:
    def __init__(self):
        self.adj = defaultdict(list)   # adjacency list

    def add_edge(self, u, v, directed=False):
        self.adj[u].append(v)
        if not directed:
            self.adj[v].append(u)

    def bfs(self, start):              # O(V + E)
        visited = {start}
        queue = deque([start])
        order = []
        while queue:
            node = queue.popleft()
            order.append(node)
            for neighbor in self.adj[node]:
                if neighbor not in visited:
                    visited.add(neighbor)
                    queue.append(neighbor)
        return order

    def dfs(self, start):              # O(V + E)
        visited = set()
        order = []
        def _dfs(node):
            visited.add(node)
            order.append(node)
            for nb in self.adj[node]:
                if nb not in visited:
                    _dfs(nb)
        _dfs(start)
        return order

    def has_path(self, start, end):    # BFS-based
        visited = {start}
        queue = deque([start])
        while queue:
            node = queue.popleft()
            if node == end:
                return True
            for nb in self.adj[node]:
                if nb not in visited:
                    visited.add(nb); queue.append(nb)
        return False

class Graph {
  private adj = new Map<string, string[]>();

  private ensure(node: string) {
    if (!this.adj.has(node)) this.adj.set(node, []);
  }

  addEdge(u: string, v: string, directed = false): void {
    this.ensure(u); this.ensure(v);
    this.adj.get(u)!.push(v);
    if (!directed) this.adj.get(v)!.push(u);
  }

  bfs(start: string): string[] {     // O(V + E)
    const visited = new Set([start]);
    const queue = [start];
    const order: string[] = [];
    while (queue.length) {
      const node = queue.shift()!;
      order.push(node);
      for (const nb of (this.adj.get(node) ?? [])) {
        if (!visited.has(nb)) { visited.add(nb); queue.push(nb); }
      }
    }
    return order;
  }

  dfs(start: string): string[] {     // O(V + E)
    const visited = new Set<string>();
    const order: string[] = [];
    const recurse = (node: string) => {
      visited.add(node); order.push(node);
      for (const nb of (this.adj.get(node) ?? []))
        if (!visited.has(nb)) recurse(nb);
    };
    recurse(start);
    return order;
  }
}

Tries (Prefix Trees)

A trie (pronounced "try," short for retrieval) is a tree where each node represents a single character. Words are formed by following paths from the root. Searching for a word or prefix takes exactly O(L) steps, where L is the number of characters — it doesn't matter if a million words are stored. This makes tries the engine behind autocomplete.

Think of it like… a physical dictionary with shared spine letters. All words starting with "app" share the same A→P→P path through the trie. Once you reach the "app" node, branching leads to "apple," "append," "application." You never recheck whether a word starts with "app" — you're already there.

Common Operations

OperationTimeNotes
Insert wordO(L)L = length of word
Search exact wordO(L)Check end-of-word marker at last char
Prefix search (autocomplete)O(L + results)Navigate to prefix node, then collect all endings

class TrieNode:
    def __init__(self):
        self.children = {}   # char → TrieNode
        self.is_end = False  # marks end of a complete word

class Trie:
    def __init__(self):
        self.root = TrieNode()

    def insert(self, word):          # O(L)
        node = self.root
        for ch in word:
            if ch not in node.children:
                node.children[ch] = TrieNode()
            node = node.children[ch]
        node.is_end = True

    def search(self, word):          # O(L) — exact match
        node = self.root
        for ch in word:
            if ch not in node.children:
                return False
            node = node.children[ch]
        return node.is_end

    def starts_with(self, prefix):   # O(L + matches) — autocomplete
        node = self.root
        for ch in prefix:
            if ch not in node.children:
                return []
            node = node.children[ch]
        return self._collect(node, prefix)

    def _collect(self, node, prefix):
        words = []
        if node.is_end:
            words.append(prefix)
        for ch, child in node.children.items():
            words.extend(self._collect(child, prefix + ch))
        return words

      if (!node.children.has(ch)) node.children.set(ch, new TrieNode());
      node = node.children.get(ch)!;

    node.isEnd = true;

    if (node.isEnd) words.push(prefix);
    for (const [ch, child] of node.children) {
      words.push(...this._collect(child, prefix + ch));
    }
    return words;

Disjoint Set (Union Find)

A disjoint set tracks elements grouped into non-overlapping sets, and efficiently answers: "Are these two elements in the same group?" and "Merge the groups containing these two elements." Two optimizations — union by rank and path compression — bring both operations to nearly O(1) (formally O(α(n)), where α is the inverse Ackermann function, which is less than 5 for any practical input size).

Think of it like… tracking friend groups at a party. Initially everyone is a lone group. When Alice meets Bob, their groups merge. Later, when you ask "are Alice and Carol in the same group?" you don't trace every introduction — you look up each person's group leader, and compare.

Common Operations

OperationTime (with both optimizations)Notes
Find (find group root)O(α(n)) ≈ O(1)Path compression flattens future lookups
Union (merge two groups)O(α(n)) ≈ O(1)Union by rank keeps trees shallow
Connected (same group?)O(α(n)) ≈ O(1)Just compare roots

class UnionFind:
    def __init__(self, n):
        self.parent = list(range(n))   # each element starts as its own root
        self.rank   = [0] * n          # tree height estimate

    def find(self, x):                 # O(α(n)) with path compression
        if self.parent[x] != x:
            # Path compression: point directly to root after finding it
            self.parent[x] = self.find(self.parent[x])
        return self.parent[x]

    def union(self, x, y):             # O(α(n))
        rx, ry = self.find(x), self.find(y)
        if rx == ry:
            return False               # already in same group
        # Union by rank: attach smaller tree under larger tree's root
        if self.rank[rx] < self.rank[ry]:
            rx, ry = ry, rx
        self.parent[ry] = rx
        if self.rank[rx] == self.rank[ry]:
            self.rank[rx] += 1
        return True

    def connected(self, x, y):        # O(α(n))
        return self.find(x) == self.find(y)

class UnionFind {
  private parent: number[];
  private rank: number[];

  constructor(n: number) {
    this.parent = Array.from({ length: n }, (_, i) => i);
    this.rank   = new Array(n).fill(0);
  }

  find(x: number): number {              // O(α(n)) with path compression
    if (this.parent[x] !== x) {
      this.parent[x] = this.find(this.parent[x]);
    }
    return this.parent[x];
  }

  union(x: number, y: number): boolean { // O(α(n))
    const rx = this.find(x), ry = this.find(y);
    if (rx === ry) return false;
    if (this.rank[rx] < this.rank[ry]) {
      this.parent[rx] = ry;
    } else if (this.rank[rx] > this.rank[ry]) {
      this.parent[ry] = rx;
    } else {
      this.parent[ry] = rx;
      this.rank[rx]++;
    }
    return true;
  }

  connected(x: number, y: number): boolean {
    return this.find(x) === this.find(y);
  }
}

Bloom Filter

A bloom filter is a probabilistic, space-efficient membership structure. It can definitively tell you an item is not in the set, but may occasionally report a false positive (claiming an item is in the set when it isn't). No false negatives ever occur. The tradeoff: it uses a tiny fraction of the memory a hashset would need, and cannot store or return actual values — only yes/maybe or no.

Think of it like… a checklist of smudged fingerprints. If a fingerprint doesn't match any smudge, the suspect was definitely not here. If it does match, they probably were here — but the smudge might overlap with someone else's. You'd then do a more expensive check to confirm.

Delete elementsNot supportedSupported

Add / Check timeO(k) — k hash functionsO(1)

import hashlib

class BloomFilter:
    """
    Space-efficient probabilistic membership structure.
    No false negatives. Possible false positives.
    Cannot delete entries once added.
    """
    def __init__(self, size=10_000, num_hashes=3):
        self.size = size
        self.num_hashes = num_hashes
        self.bits = bytearray(size)   # one bit per slot (using bytes here)

    def _positions(self, item):
        return [
            int(hashlib.md5(f"{seed}:{item}".encode()).hexdigest(), 16) % self.size
            for seed in range(self.num_hashes)
        ]

    def add(self, item):              # O(k)
        for pos in self._positions(item):
            self.bits[pos] = 1

    def might_contain(self, item):    # O(k) — True means "probably yes"
        return all(self.bits[pos] for pos in self._positions(item))

# Web crawler: skip already-seen URLs cheaply
bf = BloomFilter(size=100_000, num_hashes=3)
for url in ["https://example.com", "https://python.org"]:
    bf.add(url)

# Definite NO — safe to crawl
print(bf.might_contain("https://new-site.com"))   # False → definitely not seen

# Probable YES — skip or do a more expensive check before crawling
print(bf.might_contain("https://example.com"))    # True → probably seen

class BloomFilter {
  private bits: Uint8Array;
  private numHashes: number;

  constructor(size = 10_000, numHashes = 3) {
    this.bits = new Uint8Array(size);
    this.numHashes = numHashes;
  }

  // Simple polynomial hash with different seeds
  private hash(item: string, seed: number): number {
    let h = seed * 2654435761;
    for (const ch of item) h = (Math.imul(h, 31) + ch.charCodeAt(0)) | 0;
    return Math.abs(h) % this.bits.length;
  }

  add(item: string): void {              // O(k)
    for (let s = 0; s < this.numHashes; s++) {
      this.bits[this.hash(item, s)] = 1;
    }
  }

  mightContain(item: string): boolean {  // O(k)
    for (let s = 0; s < this.numHashes; s++) {
      if (!this.bits[this.hash(item, s)]) return false;
    }
    return true;
  }
}

LRU Cache (Least Recently Used)

An LRU cache is a fixed-size cache that automatically evicts the item that has not been accessed for the longest time when space runs out. It combines two structures: a hashmap for O(1) lookup, and a doubly linked list to efficiently track the recency order. When an item is accessed, it moves to the front of the list. The back of the list is always the eviction candidate.

Think of it like… a desk with limited space. You keep the files you're currently using on the desk. When the desk is full and you need a new file, you put away the one you haven't touched in the longest time. Files you use often stay on the desk; files gathering dust get filed away.

Operations

OperationTimeHow
get(key)O(1)Hashmap lookup, then move node to front of list
put(key, value)O(1)Hashmap insert, add to front; if over capacity, remove from back

from collections import OrderedDict

class LRUCache:
    """
    OrderedDict maintains insertion order and supports move_to_end(),
    making it a natural LRU cache backed by a hashmap + doubly linked list.
    All operations are O(1).
    """
    def __init__(self, capacity):
        self.capacity = capacity
        self.cache = OrderedDict()

    def get(self, key):               # O(1)
        if key not in self.cache:
            return -1
        self.cache.move_to_end(key)   # mark as most recently used
        return self.cache[key]

    def put(self, key, value):        # O(1)
        if key in self.cache:
            self.cache.move_to_end(key)
        self.cache[key] = value
        if len(self.cache) > self.capacity:
            self.cache.popitem(last=False)  # evict least recently used (front)

# Example with capacity 3
cache = LRUCache(3)
cache.put("a", 1)
cache.put("b", 2)
cache.put("c", 3)

cache.get("a")         # access "a" — it's now the most recent
cache.put("d", 4)      # cache full → "b" is evicted (least recently used)

print(cache.get("b"))  # -1  — evicted!
print(cache.get("a"))  # 1   — still here
print(cache.get("c"))  # 3   — still here
print(cache.get("d"))  # 4   — just added
TypeScript 
// JavaScript's Map preserves insertion order, making it a clean LRU foundation
class LRUCache {
  private capacity: number;
  private cache: Map<string, number>;

  constructor(capacity: number) {
    this.capacity = capacity;
    this.cache = new Map();
  }

  get(key: string): number {          // O(1)
    if (!this.cache.has(key)) return -1;
    const val = this.cache.get(key)!;
    // Move to end = most recently used
    this.cache.delete(key);
    this.cache.set(key, val);
    return val;
  }

  put(key: string, value: number): void { // O(1)
    if (this.cache.has(key)) this.cache.delete(key);
    this.cache.set(key, value);
    if (this.cache.size > this.capacity) {
      // First key in Map = least recently used
      const lruKey = this.cache.keys().next().value;
      this.cache.delete(lruKey);
    }
  }
}

const cache = new LRUCache(3);
cache.put("a", 1); cache.put("b", 2); cache.put("c", 3);
cache.get("a");         // access "a" — most recent
cache.put("d", 4);      // "b" evicted

console.log(cache.get("b")); // -1  — evicted
console.log(cache.get("a")); // 1
console.log(cache.get("d")); // 4
