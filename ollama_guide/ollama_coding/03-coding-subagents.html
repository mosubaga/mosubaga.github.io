1. A practical architecture

A subagent is a specialized role with its own task and output contract. It does not require a separate running model: you can call the same Ollama model with different system prompts, or select different models by role.

text
User task
   -> Planner: requirements + file plan
   -> Documentation researcher: Context7 + version check
   -> Coder: implementation from vetted references
   -> Reviewer/refactorer: analyze API, error handling, style
   -> Test designer: propose unit/integration tests
   -> Validator: run an allowlisted test command in sandbox
   -> Human: approve patch before applying to repo

Start with a sequential workflow. Parallel agents add cost and conflict risk. Each step receives the previous results, and the final result should distinguish generated code from verified execution.

2. Python program

See examples/agent_python.py. It uses standard Python, urllib.request, and the local Ollama /api/chat endpoint. Its roles: planner, coder, reviewer, and tester. It retrieves Context7 context using the REST API when a key is provided and saves outputs as Markdown proposals in output/. Existing proposal files are not overwritten; choose a new directory with --out for each run.

bash
# macOS / Linux
export CONTEXT7_API_KEY='YOUR_KEY'
export OLLAMA_MODEL='qwen2.5-coder:7b'
python examples/agent_python.py --library FastAPI --language Python \
  --task 'Create a small health-check endpoint with pytest tests'
powershell
# PowerShell
$env:CONTEXT7_API_KEY = 'YOUR_KEY'
$env:OLLAMA_MODEL = 'qwen2.5-coder:7b'
python examples/agent_python.py --library FastAPI --language Python --task 'Create a health-check API and tests'

3. TypeScript program

See examples/agent_typescript.ts. Requires Node >=20 and tsx (for running TypeScript source).

bash
npm install -D tsx typescript @types/node
npx tsx examples/agent_typescript.ts --library Express --language TypeScript \
  --task 'Implement a typed GET /health endpoint with tests'

4. Sample tool-calling interface (conceptual)

For a genuinely autonomous agent, add an explicit, narrowly scoped tool registry rather than letting model output execute shell code:

python
ALLOWED_TOOLS = {
    "read_project_file": "Read files within an approved project root",
    "get_library_docs": "Query Context7 with a verified library ID",
    "propose_patch": "Write diff proposals to a review directory",
    "run_tests": "Run preconfigured test commands in a sandbox",
}

Implement tool execution in host code. Validate tool arguments, enforce path restrictions, disable network access for test runs where feasible, and require approval for destructive operations. Never directly eval() tool arguments or execute raw shell strings returned by an LLM.

5. Validation commands by language

Language Typical validation (configure per project)
Python python -m pytest, ruff check ., mypy .
TypeScript/JavaScript npm test, npx tsc --noEmit, npx eslint .
HTML/CSS HTML validator, Stylelint, Playwright browser checks
Java mvn test or ./gradlew test
Go go test ./..., go vet ./...
C++ cmake --build build, ctest --test-dir build --output-on-failure
Perl prove -lr t, perl -c script.pl
Julia julia --project=. -e 'using Pkg; Pkg.test()'

These commands can execute project-supplied scripts or untrusted code; run inside an isolated/containerized workspace and obtain user approval first. Test output is evidence, not a correctness proof.

6. Agent prompts

text
Planner: Specify output files, dependencies, acceptance criteria, and test strategy.
Coder: Use retrieved docs only where applicable; separate assumptions and code.
Reviewer: Flag unsupported methods, security bugs, race conditions, and incompatibilities.
Tester: Generate runnable positive/negative tests and provide exact commands.
Validator: Report actual output, exit status, and environment; do not fabricate passes.

7. Scaling up

When ready, add an explicit tool-call loop and structured response validation; preserve tool-call history and guard iteration counts. For larger projects, consider a repository-aware editor/agent client capable of using Ollama and Context7, but verify its current support and MCP setup rather than assuming the integration is automatic.
