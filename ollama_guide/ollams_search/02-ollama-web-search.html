Web Search with Ollama's Built-in API

Use Ollama's hosted web search and web fetch API as tools for a local model.

1. What the API provides

Ollama offers a hosted web search service with two REST endpoints, plus matching functions in the Python and JavaScript libraries:

  • POST https://ollama.com/api/web_search takes a query and optional max_results (default 5, maximum 10) and returns title, url and content for each result.
  • POST https://ollama.com/api/web_fetch takes a url and returns the page title, content and links.

The search runs on ollama.com, not on your machine. The model that reads the results can still be a local one.

2. Create an API key

The API requires a free Ollama account. Create a key at ollama.com/settings/keys and export it:

bash
export OLLAMA_API_KEY="your_api_key_here"

In Windows PowerShell:

powershell
$env:OLLAMA_API_KEY = 'your_api_key_here'

Keep the key out of committed files and out of screenshots.

3. Test with curl

bash
curl https://ollama.com/api/web_search \
  --header "Authorization: Bearer $OLLAMA_API_KEY" \
  -d '{"query": "what is ollama?", "max_results": 3}'
json
{
  "results": [
    {
      "title": "Ollama",
      "url": "https://ollama.com/",
      "content": "Cloud models are now available..."
    }
  ]
}

If this call fails, fix the key before involving a model.

4. Python and JavaScript libraries

bash
python -m pip install ollama
python
import ollama

results = ollama.web_search('What is Ollama?')
print(results)

page = ollama.web_fetch('https://ollama.com')
print(page.title)

The JavaScript library exposes the same calls as webSearch and webFetch. Each takes a request object:

bash
npm init -y
npm install ollama
npm install -D typescript tsx @types/node
typescript
import { Ollama } from 'ollama';

const client = new Ollama();

async function main(): Promise<void> {
  const results = await client.webSearch({ query: 'What is Ollama?' });
  console.log(JSON.stringify(results, null, 2));

  const page = await client.webFetch({ url: 'https://ollama.com' });
  console.log(page.title);
}

main().catch(console.error);
bash
npx tsx search.ts

Both libraries read OLLAMA_API_KEY from the environment. The TypeScript examples wrap their code in main() because a project created by npm init -y is CommonJS, where top-level await is not available.

5. Build a search agent

Pass web_search and web_fetch as tools to a local model and run the loop from chapter 01:

python
from ollama import chat, web_fetch, web_search

available_tools = {'web_search': web_search, 'web_fetch': web_fetch}
messages = [{'role': 'user', 'content': 'What is the latest stable version of Python?'}]

while True:
    response = chat(
        model='qwen3:8b',
        messages=messages,
        tools=[web_search, web_fetch],
        think=True,
        options={'num_ctx': 32000},
    )
    messages.append(response.message)
    if not response.message.tool_calls:
        print(response.message.content)
        break
    for call in response.message.tool_calls:
        tool = available_tools.get(call.function.name)
        result = str(tool(**call.function.arguments)) if tool else 'Tool not found'
        # Truncate the result so it fits in the context window
        messages.append({'role': 'tool', 'tool_name': call.function.name, 'content': result[:8000]})

The Python library builds the tool descriptions from the functions themselves. think=True lets Qwen 3 reason about whether to search before it answers.

The same loop in TypeScript. The JavaScript library does not derive a tool description from a function, so you write the JSON schema by hand:

typescript
import { Ollama, type Message, type Tool } from 'ollama';

const client = new Ollama();

const tools: Tool[] = [{
  type: 'function',
  function: {
    name: 'web_search',
    description: 'Search the web and return titles, URLs and content snippets.',
    parameters: {
      type: 'object',
      properties: { query: { type: 'string', description: 'The search query.' } },
      required: ['query'],
    },
  },
}];

async function main(): Promise<void> {
  const messages: Message[] = [{ role: 'user', content: 'What is the latest stable version of Python?' }];
  while (true) {
    const response = await client.chat({
      model: 'qwen3:8b', messages, tools, think: true, options: { num_ctx: 32000 },
    });
    messages.push(response.message);
    const calls = response.message.tool_calls ?? [];
    if (calls.length === 0) {
      console.log(response.message.content);
      break;
    }
    for (const call of calls) {
      const result = await client.webSearch({ query: String(call.function.arguments.query) });
      // Truncate the result so it fits in the context window
      messages.push({ role: 'tool', tool_name: call.function.name, content: JSON.stringify(result).slice(0, 8000) });
    }
  }
}

main().catch(console.error);

Fuller versions with a system prompt, a step limit, error handling and both tools are in examples/search_agent.py and examples/search_agent.ts:

bash
python search_agent.py "What is the latest stable version of Python?"
npx tsx search_agent.ts "What is the latest stable version of Python?"

6. Raise the context length

Search results can add thousands of tokens. Ollama defaults to a 4k context on machines with less than 24 GiB of VRAM, which truncates results before the model reads them. Ollama's web search page recommends at least about 32,000 tokens, and its context length page recommends 64,000 for web search and agents.

Set it per request with options={'num_ctx': 32000} in Python or options: { num_ctx: 32000 } in TypeScript as above, or for the whole server:

bash
OLLAMA_CONTEXT_LENGTH=32000 ollama serve

In the Ollama desktop app, use the context length slider under Settings. Then confirm what was allocated:

bash
ollama ps

Important: A larger context uses more memory. If ollama ps shows part of the model on CPU, responses become much slower; lower the context length or use a smaller model such as qwen3:4b.

7. Limits

  • The API needs an internet connection and an Ollama account; check your account for current usage limits.
  • The query text and fetched URLs are sent to ollama.com.
  • Search snippets are short. Use web_fetch on the most relevant result when the snippet is not enough.
  • The model can still misread or over-summarize results. See chapter 05.
