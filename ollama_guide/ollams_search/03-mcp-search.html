Web Search through MCP

Answer: yes, with an MCP host

The Model Context Protocol (MCP) is a standard way to offer tools to a model. Many web search tools are published as MCP servers. Ollama is an LLM runtime, not an MCP client, so you need a host application between them that connects to the MCP server and uses Ollama for inference.

text
Ollama (qwen3, local) <--> MCP host / client <--> MCP search server <--> the web

The host lists the server's tools for the model, runs the tool calls the model makes, and returns the results. It is the same loop as in chapter 01, already written for you.

Hosted APIs change their free tiers and terms; check each provider before depending on one.

3. Recipe: ollmcp + DuckDuckGo (no API key)

Requirements: Ollama with qwen3:8b, Python 3.11+, and uv for the uvx command.

bash
# Install the MCP client
uv tool install --upgrade ollmcp

# Register the DuckDuckGo MCP server (everything after -- is the command to run)
ollmcp mcp add ddg-search -- uvx duckduckgo-mcp-server

# Confirm it is registered
ollmcp mcp list

# Start chatting with the local model
ollmcp --model qwen3:8b

Inside the client, type /help for commands and /tools to confirm that search and fetch_content are enabled. Then ask something that needs current information:

text
Search the web: what is the latest stable version of Python, and when was it released? Cite your sources.

ollmcp shows each tool call and, with Human-in-the-Loop enabled, asks for approval before running it. Raise the context window in the client's model configuration (num_ctx); see chapter 05.

4. Alternative host: mcphost

bash
go install github.com/mark3labs/mcphost@latest

Create ~/.mcphost.yml:

yaml
mcpServers:
  ddg-search:
    type: "local"
    command: ["uvx", "duckduckgo-mcp-server"]

model: "ollama/qwen3:8b"
max-steps: 10
bash
mcphost

You can also pass the model on the command line with mcphost -m ollama/qwen3:8b.

5. Ollama's web search MCP server

Ollama publishes a small Python MCP server that exposes its web search and web fetch API. Download web-search-mcp.py from the ollama-python examples, then register it in your host. The generic configuration, as used by Cline and similar clients:

json
{
  "mcpServers": {
    "web_search_and_fetch": {
      "type": "stdio",
      "command": "uv",
      "args": ["run", "path/to/web-search-mcp.py"],
      "env": { "OLLAMA_API_KEY": "your_api_key_here" }
    }
  }
}

With ollmcp, the equivalent is:

bash
ollmcp mcp add --env OLLAMA_API_KEY=your_api_key_here ollama-search -- uv run path/to/web-search-mcp.py

Exact file location and schema vary by client. Keep credentials out of committed files.

6. Open WebUI

Open WebUI connects to MCP servers over Streamable HTTP, not stdio, so start the search server in that mode:

bash
uvx duckduckgo-mcp-server --transport streamable-http --port 7070

Then, as an administrator, open Settings > Integrations, and under External Tool Servers add a connection with Type set to MCP (Streamable HTTP) and the server URL. Choosing the OpenAPI type for an MCP server is a common mistake. Consult the current Open WebUI MCP guide for the endpoint path and authentication settings.

Open WebUI also has a built-in web search feature that does not use MCP; see chapter 04.

7. Keep the tool set small

  • Every tool description consumes context, and small models choose worse as the list grows. Enable one search tool and one fetch tool; disable the rest.
  • An MCP server is a program running on your machine with your permissions. Install servers only from sources you trust and read what they do.
  • MCP does not make the model better at using tools. If the model ignores the search tool or sends wrong arguments, the fix is a clearer prompt or a stronger model, not a different server.
