Library guide · Fast DataFrames

Polars

A fast, multi-threaded DataFrame library built around expressions and lazy queries. This page covers reading data and analysing it.

Polars is a DataFrame library written in Rust with a Python API. It uses every CPU core by default, stores data in the Apache Arrow columnar format, and has a lazy query engine that optimises your whole pipeline before running it. For data preparation and analysis on anything from a few thousand rows to datasets larger than memory, it is often many times faster than pandas while staying very readable.

pip install polars pyarrow

pyarrow is optional; it is only needed for conversions such as df.to_pandas(). The examples on this page also use NumPy and scikit-learn (pip install numpy scikit-learn).

Why Polars?

Fast by default

Multi-threaded, vectorised execution on Arrow memory, with no extra configuration.

Lazy queries

scan_* functions build a plan; the optimiser pushes filters and column selection down to the file reader.

Expressions

Composable pl.col(...) expressions describe what to compute, and Polars runs them in parallel.

Larger than memory

The streaming engine processes data in batches, so files bigger than your RAM still work.

Before you run the examples

Run this script once. It creates sales.csv and sales.parquet (5,000 orders from 2025) in your working folder, so every other example on this page can be copied and run as-is.

import numpy as np
import polars as pl

# Create a realistic sample file so every example below can be run as-is
rng = np.random.default_rng(0)
n = 5_000
activity = rng.gamma(0.6, 1.0, 400)            # some customers buy far more often
activity /= activity.sum()
sales = pl.DataFrame({
    "order_id": np.arange(1, n + 1),
    "order_date": pl.date_range(pl.date(2025, 1, 1), pl.date(2025, 12, 31), "1d", eager=True)
                    .sample(n, with_replacement=True, seed=0).sort(),
    "customer_id": rng.choice(np.arange(1, 401), size=n, p=activity),
    "region": rng.choice(["East", "West", "North", "South"], n),
    "category": rng.choice(["Electronics", "Home", "Books", "Toys"], n),
    "quantity": rng.integers(1, 6, n),
    "unit_price": rng.gamma(2.0, 30.0, n).round(2),
})
# sprinkle in some missing prices, like real data
sales = sales.with_columns(
    pl.when(pl.Series(rng.random(n) < 0.02)).then(None).otherwise(pl.col("unit_price")).alias("unit_price")
)
sales.write_csv("sales.csv")
sales.write_parquet("sales.parquet")
print(sales.head())

Part 1: Reading Data

Eager reading with read_*

pl.read_csv, pl.read_parquet, pl.read_json, pl.read_excel and pl.read_database load data into a DataFrame immediately. You can limit columns and rows and override types during the read.

import polars as pl

# Eager: read the whole file into memory now
df = pl.read_csv("sales.csv", try_parse_dates=True)
print(df.shape)
print(df.schema)

# Parquet keeps column types and is much faster to load
df = pl.read_parquet("sales.parquet")

# Only read what you need
small = pl.read_csv("sales.csv", columns=["order_id", "region", "unit_price"], n_rows=1_000)
print(small.head(3))

# Explicit types (useful for IDs, codes and memory savings)
typed = pl.read_csv(
    "sales.csv",
    schema_overrides={"region": pl.Categorical, "customer_id": pl.Int32},
    try_parse_dates=True,
)
print(typed.schema)
Supported sources:
  • CSV / TSV, Parquet, JSON and NDJSON, Arrow IPC (Feather), Excel, Avro
  • Databases via pl.read_database (SQLAlchemy / ADBC connections) or pl.read_database_uri
  • Cloud storage: pass s3://, gs:// or az:// paths directly
  • Many files at once with glob patterns: pl.scan_parquet("data/*.parquet")
Useful read options:
  • columns=[...] - read only some columns
  • n_rows= - preview a large file quickly
  • schema_overrides={...} - force dtypes
  • try_parse_dates=True - detect date columns
  • null_values=["NA", ""] - custom missing markers

Lazy reading with scan_*

pl.scan_csv and pl.scan_parquet return a LazyFrame. Nothing is read until you call .collect(), so Polars can read only the needed columns (projection pushdown) and skip rows early (predicate pushdown). Prefer the lazy API for anything beyond quick exploration.

import polars as pl

# Lazy: build a query plan; nothing is read until .collect()
query = (
    pl.scan_parquet("sales.parquet")            # also: pl.scan_csv("sales.csv")
      .filter(pl.col("region") == "East")
      .select("order_date", "category", "quantity", "unit_price")
)
print(query.explain())          # shows predicate & projection pushdown

east = query.collect()
print(east.head())

# For files larger than memory, run the query on the streaming engine
big_result = query.collect(engine="streaming")
print(big_result.height)

Part 2: Analysing Data

First look at a dataset

import polars as pl

df = pl.read_parquet("sales.parquet")

print(df.head())
print(df.describe())                 # count, nulls, mean, std, min, quartiles, max
print(df.null_count())
print(df["region"].value_counts(sort=True))
print(df.select(pl.col("unit_price").quantile(0.95).alias("p95_price")))

Expressions: select, filter and with_columns

Almost everything in Polars is an expression such as pl.col("unit_price").fill_null(...). Expressions are used inside contexts:

  • select(...) - choose or compute columns (the result has only those columns)
  • with_columns(...) - add or replace columns, keeping the rest
  • filter(...) - keep rows where a boolean expression is true
  • group_by(...).agg(...) - aggregate expressions per group
import polars as pl

df = pl.read_parquet("sales.parquet")

clean = (
    df
    # fill missing prices with the median price of the same category
    .with_columns(
        pl.col("unit_price").fill_null(pl.col("unit_price").median().over("category"))
    )
    # derived columns are computed in parallel
    .with_columns(
        revenue=pl.col("quantity") * pl.col("unit_price"),
        month=pl.col("order_date").dt.month(),
        weekday=pl.col("order_date").dt.weekday(),         # Monday = 1 ... Sunday = 7
    )
    .with_columns(is_weekend=pl.col("weekday") >= 6)
    .filter(pl.col("revenue") > 0)
)

print(clean.select("order_id", "category", "revenue", "month", "is_weekend").head())

# Conditional logic with when / then / otherwise
tiers = clean.with_columns(
    tier=pl.when(pl.col("revenue") >= 300).then(pl.lit("high"))
           .when(pl.col("revenue") >= 100).then(pl.lit("mid"))
           .otherwise(pl.lit("low"))
)
print(tiers["tier"].value_counts(sort=True))

Group-by, pivot and time-based aggregation

Aggregations take any number of expressions. pl.len() counts rows; group_by_dynamic groups by calendar windows such as weeks or months.

import polars as pl

df = (
    pl.read_parquet("sales.parquet")
      .drop_nulls("unit_price")
      .with_columns(revenue=pl.col("quantity") * pl.col("unit_price"))
)

by_region = (
    df.group_by("region")
      .agg(
          orders=pl.len(),
          revenue=pl.col("revenue").sum(),
          avg_order=pl.col("revenue").mean(),
          top_category=pl.col("category").mode().first(),
      )
      .sort("revenue", descending=True)
)
print(by_region)

# Pivot: regions as rows, categories as columns
pivot = df.pivot(on="category", index="region", values="revenue", aggregate_function="sum").sort("region")
print(pivot)

# Monthly time series (data must be sorted by the date column)
monthly = (
    df.sort("order_date")
      .group_by_dynamic("order_date", every="1mo")
      .agg(revenue=pl.col("revenue").sum(), orders=pl.len())
)
print(monthly.head())

Window functions and joins

.over("column") computes an aggregate per group but returns a value for every row, ideal for features like "customer's total spend" or "rank within region". Joins work like SQL: how="inner" | "left" | "full" | "semi" | "anti" | "cross".

import polars as pl

df = (
    pl.read_parquet("sales.parquet")
      .drop_nulls("unit_price")
      .with_columns(revenue=pl.col("quantity") * pl.col("unit_price"))
)

customer_features = df.with_columns(
    # window functions: aggregate per group but keep every row
    customer_total=pl.col("revenue").sum().over("customer_id"),
    customer_orders=pl.len().over("customer_id"),
    share_of_region=pl.col("revenue") / pl.col("revenue").sum().over("region"),
    rank_in_region=pl.col("revenue").rank("dense", descending=True).over("region"),
)
print(customer_features.select("customer_id", "region", "revenue",
                               "customer_total", "rank_in_region").head())

# Joins: enrich orders with a lookup table
targets = pl.DataFrame({"region": ["East", "West", "North", "South"],
                        "monthly_target": [9_000, 8_500, 7_000, 7_500]})
joined = df.join(targets, on="region", how="left")
print(joined.select("order_id", "region", "monthly_target").head(3))

Part 3: From Polars to Machine Learning

A common real-world task: turn an order log into one row per customer, then predict who will buy again. The whole feature pipeline below is lazy, so Polars optimises it as a single query. The final DataFrame converts to NumPy with .to_numpy() for scikit-learn.

import polars as pl
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.model_selection import train_test_split
from sklearn.metrics import roc_auc_score

orders = (
    pl.scan_parquet("sales.parquet")
      .drop_nulls("unit_price")
      .with_columns(revenue=pl.col("quantity") * pl.col("unit_price"))
)

# One row per customer: features from the first 9 months, label = bought in Q4?
cutoff = pl.date(2025, 10, 1)
features = (
    orders.filter(pl.col("order_date") < cutoff)
          .group_by("customer_id")
          .agg(
              n_orders=pl.len(),
              total_spend=pl.col("revenue").sum(),
              avg_spend=pl.col("revenue").mean(),
              n_categories=pl.col("category").n_unique(),
              days_since_last=(cutoff - pl.col("order_date").max()).dt.total_days(),
          )
)
labels = (
    orders.filter(pl.col("order_date") >= cutoff)
          .select("customer_id").unique()
          .with_columns(bought_q4=pl.lit(1))
)
data = (
    features.join(labels, on="customer_id", how="left")
            .with_columns(pl.col("bought_q4").fill_null(0))
            .collect()
)

X = data.drop("customer_id", "bought_q4").to_numpy()
y = data["bought_q4"].to_numpy()
X_train, X_test, y_train, y_test = train_test_split(X, y, stratify=y, random_state=0)

model = HistGradientBoostingClassifier(random_state=0).fit(X_train, y_train)
print(f"customers: {data.height}, ROC AUC: {roc_auc_score(y_test, model.predict_proba(X_test)[:, 1]):.3f}")

# Need pandas for a plotting library?  data.to_pandas()  (requires pyarrow)

Features are computed only from orders before the cutoff date and the label only from orders after it. Respecting time in this way prevents data leakage.

Tips and Common Pitfalls

Think in columns

Avoid map_elements (Python functions per row) where a built-in expression exists. Native expressions are often 10-100× faster.

Strings in expressions

pl.col("x") is a column, pl.lit("x") is a literal value. In when/then use pl.lit for constant strings.

Sort for time windows

group_by_dynamic and rolling require the time column to be sorted first.

Inspect the plan

lf.explain() shows the optimised query; lf.collect(engine="streaming") processes out-of-core data.

Write efficiently

df.write_parquet() or lf.sink_parquet() (streaming) keep types and compress well.

Interoperability

pl.from_pandas(pdf), df.to_pandas(), df.to_numpy() and pl.from_numpy(arr) convert between libraries.

Polars Best Practices

1. Start lazy: use scan_* + collect() so the optimiser can do its work.

2. Keep everything in expressions: chain with_columns, filter and agg rather than looping in Python.

3. Use Parquet: it is typed, compressed and enables pushdown on read.

4. Set dtypes deliberately: Categorical, Int32 and Float32 can cut memory dramatically.

5. Convert at the boundary: do the heavy lifting in Polars, then call to_numpy() or to_pandas() just before modelling or plotting.
