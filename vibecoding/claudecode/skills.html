Quality & Productivity

Using Skills

A Skill packages a piece of expertise — a checklist, a workflow, a set of scripts — so Claude Code can load it automatically whenever the task matches, instead of you re-explaining it every session.

What a Skill is

A SKILL.md file, loaded on demand

Skills live as a small folder with a SKILL.md file — a name, a trigger description, and instructions — plus any helper scripts or reference files it needs. Claude Code reads the short description of every available skill up front, and only loads the full instructions when a task actually matches it. That keeps your context window clean while still giving you unlimited specialized knowledge on tap.

.claude/skills/api-review/SKILL.md 
---
name: api-review
description: Review new or changed REST endpoints for consistent error shapes, auth checks, and input validation. Use whenever routes/ or controllers/ change.
---

# API Review Checklist
1. Every endpoint validates input before touching the DB.
2. Auth middleware runs before the handler, not inside it.
3. Errors return { error: { code, message } }, never a bare string.
4. New endpoints are added to the OpenAPI spec in docs/openapi.yaml.

Where they help

Skills worth building for most teams

Quality

Code review checklist

Encodes your team's actual review standards — naming, error handling, test coverage — so every review is consistent, not whatever the reviewer remembered that day.

Productivity

Changelog / release notes writer

Turns a range of commits into release notes in your house style, without you re-explaining the format every release.

Quality

Database migration helper

Knows your migration tool's conventions, how to write a safe backfill, and what "never do this in a migration" looks like.

Productivity

API docs generator

Keeps endpoint documentation in sync with the actual route handlers, in a fixed template, on request.

Quality

Security review pass

Walks changed code against an OWASP-style checklist before it ships — the same checklist, every time, not best-effort memory.

Productivity

Test scaffolding

Generates test files that match your project's existing test structure and naming, instead of a generic template.

Getting it right

What makes a Skill actually get used

  1. Write the description for triggering, not for humans. It should name concrete situations and file types — "use when editing routes/ or controllers/" — so Claude Code reliably recognizes when to load it.
  2. Keep each Skill narrow. One job per Skill. A "backend helper" that tries to cover migrations, API design, and testing will trigger inconsistently and dilute its own instructions.
  3. Put the checklist ahead of the explanation. Skills are read by a model mid-task — lead with the actionable steps, not background theory.
  4. Version them with the codebase. Keep Skills in the repo under .claude/skills/ so they evolve alongside the conventions they describe.
