Understanding Pointers in C++

A guided tour of five small C++ programs. Each one focuses on a different side of pointers: what they are, how to use them safely, how they work with classes, and how modern C++ manages memory for you.

Start lesson 01 What is a pointer?
Who this is for

You already know basic C++ syntax (variables, if, loops, functions) and you have written object-oriented code in another language such as Java, C#, Python or JavaScript. You do not need to know anything about memory or pointers yet.

What is a pointer?

Every variable in your program lives somewhere in the computer's memory. You can picture memory as a very long street of numbered houses. Each house holds a value, and each house has a number: its address.

A pointer is a variable whose value is an address. It does not hold the data itself; it tells you where the data is. Think of it as a slip of paper with a house number written on it.

p 0x1000 int*
points to
score 42 int lives at 0x1000

The pointer p holds the address of score, not a copy of 42.

Same symbol, two jobs

In a declaration (int* p) the star says "this is a pointer type". In an expression (*p = 5) the star says "go to the target". Likewise & means "address of" in an expression, but in a declaration such as int& r it creates a reference, a different feature.

Coming from Java, C# or Python?

You have actually been using something pointer-like all along. In Java or Python, a variable that "holds" an object really holds a reference to it. Two variables can refer to the same object, and changing it through one is visible through the other.

C++ makes this explicit and gives you a choice:

The big difference: C++ has no garbage collector. Someone must decide when an object is destroyed. That "someone" is called the object's owner, and much of this course is about making ownership clear and safe.

Why use pointers at all?

Modify the caller's data

C++ copies function arguments by default. Passing an address lets a function change the original.

Polymorphism

A Animal* can point to a Dog, so the right overridden method is called at run time.

Control lifetime

Objects created dynamically can outlive the function that made them, and be shared between parts of a program.

Optional & linked data

A pointer can be nullptr ("nothing here"), and objects can link to each other, as in trees and lists.

Golden rules of pointer safety

Pointers are powerful but the compiler will not stop many mistakes. These rules appear again and again in the comments of every lesson:

  • Always initialize a pointer, to a real address or to nullptr.
  • Check for nullptr before dereferencing a pointer that might be empty.
  • The target must outlive the pointer's use. A pointer to a variable that has gone out of scope is "dangling".
  • Only delete what you got from new, exactly once, and match new[] with delete[].
  • Prefer smart pointers (std::unique_ptr, std::shared_ptr) when you own dynamic memory.

Running the programs yourself

The best way to learn is to run each program, read its output next to the code, then change something and run it again. The source files are in the cpp/ folder. With a C++17 compiler installed:

  1. Open a terminal in the folder containing the .cpp file.
  2. Compile: g++ -std=c++17 -Wall 01_basic_pointers.cpp -o basics (or use clang++).
  3. Run: ./basics (on Windows: basics.exe).
  4. Experiment: un-comment a line marked // Error and read the compiler message. Learning what the compiler rejects is part of the lesson.
No compiler on your tablet?

Paste the code into an online compiler such as Compiler Explorer or Wandbox. Every code block on this site has a Copy button.
