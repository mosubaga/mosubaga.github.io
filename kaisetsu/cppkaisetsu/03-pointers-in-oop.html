Lesson 03 Intermediate

Pointers in OOP

Where pointers meet classes. You will see how to call methods through a pointer, what this really is, how to create and destroy objects by hand with new and delete, and why polymorphism in C++ needs pointers (or references).

What the programmer wants you to learn

  • Access members through a pointer with ->.
  • Understand this, the pointer every method receives to "its" object.
  • Allocate and free objects manually, and the rules that come with it.
  • Get overridden methods to run through a base-class pointer (virtual dispatch).
  • See the rarely used but interesting pointers to members.
"Raw ownership here is educational"

The author warns up front: this lesson uses new/delete directly so you understand what is happening underneath. In real code you should prefer RAII (smart pointers), covered in Lesson 04.

The classes

Counter

  • explicit Counter(int initial = 0) : value(initial) {} is a constructor. The part after the colon is a member initializer list: it sets value to initial. = 0 is a default argument, and explicit prevents an int from silently converting into a Counter.
  • set and add return Counter&, a reference to the same object, so calls can be chained (see Section 2).
  • show() const: the const after the parameter list promises this method does not modify the object.

Animal and Dog

In Java every method can be overridden by default. In C++ a method must be marked virtual for that to work through a base-class pointer. override in Dog asks the compiler to check that it really overrides something. The destructor (~Animal) is also virtual. Section 4 shows why that matters.

Section 1: Member access

counter is an object (not a reference like in Java: the object itself lives in this variable). counter_pointer holds its address. To reach a member through the pointer you have two options:

SyntaxMeaning
(*counter_pointer).show()Dereference to get the object, then use .
counter_pointer->show()Exactly the same, but easier to read and type

The parentheses in the first form are required because . binds more tightly than *. That awkwardness is the reason -> exists. Rule of thumb: object → use .; pointer → use ->.

Section 2: The this pointer and chaining

Inside a method, this is a pointer to the object the method was called on. It is the same idea as this in Java/C# or self in Python, except that in C++ it is a real pointer, so you use this->value.

  • this->value = value;: the parameter is also named value, so this-> tells the compiler you mean the member.
  • Printing this shows the object's address.
  • return *this;: this is a pointer; *this is the object itself. Returning it as a reference lets the next call continue on the same object.

So counter_pointer->set(10).add(3).show() runs as: set to 10 → add 3 → show 13.

Section 3: Raw dynamic allocation

So far every object has been a local variable, destroyed automatically at the end of its scope. new creates an object in dynamic storage (the "heap") instead. It stays alive until you explicitly delete it.

A single object

heap_counter0x...Counter* · local
points to
Countervalue: 20dynamic storage (heap)

The pointer is a normal local variable; the object it points to is not.

  • new (std::nothrow) Counter(20): normally new throws an exception (std::bad_alloc) if memory runs out. The std::nothrow version returns nullptr instead, which is why the code checks for null. This is what <new> is included for.
  • delete heap_counter; runs the destructor and frees the memory.
  • heap_counter = nullptr; afterwards: the pointer still holds the old address, which is now invalid. Setting it to null avoids accidentally using it.

An array of objects

new Counter[3] creates three Counter objects in a row (each built with the default constructor, value 0). The loop calls set(index + 1) on each, which prints each element's address. Look at the output: the addresses go up by 4 bytes, the size of one Counter (it contains a single int).

The rules of manual memory (lines 72 and 77–79)
  • new pairs with delete; new[] must pair with delete[].
  • Never delete an object that was not created with new (such as counter).
  • Never delete twice, and never use an object after deleting it.
  • Setting one pointer to nullptr does not fix other pointers to the same object. They now dangle.
  • If an exception is thrown between new and delete, the delete is skipped and memory leaks.

Every one of these is a reason to use smart pointers.

Section 4: Polymorphism through base pointers

Animal* animal = new Dog;: the pointer's type is Animal*, but the object is a Dog. Because speak() is virtual, the call is decided at run time by the real object's type, so it prints Dog says woof. This is dynamic dispatch, the behavior you are used to from Java or C#.

When the object is deleted, both destructors run: the derived part (Dog) first, then the base part (Animal). That only happens because ~Animal() is virtual.

Why pointers are needed for polymorphism

If you write Animal a = Dog(); (no pointer), C++ copies only the Animal part into a. The Dog part is "sliced off" and a.speak() prints Animal sound. A pointer or reference refers to the full original object, so dispatch works.

Forget virtual on the destructor and...

deleting a Dog through an Animal* is undefined behavior; typically only ~Animal runs and the Dog part is never cleaned up. Rule: if a class has virtual methods, give it a virtual destructor.

Section 5: Pointers to class members

This is an advanced feature you will rarely write yourself, but it shows how far the pointer idea goes. A pointer to member does not point to a particular object's data. It says "the value member of some Counter". You supply the object later:

CodeMeaning
int Counter::* data_member = &Counter::value;"which int member of Counter": value
counter.*data_member = 50;Apply it to an object with .*
counter_pointer->*data_memberApply it to a pointer with ->*
void (Counter::* member_function)() const = &Counter::show;"which const, no-argument method": show
(counter.*member_function)();Call it on an object (parentheses required)

Since counter_pointer points to counter, every line operates on the same object.

Where is this useful? Generic code that needs to choose which field or method to use at run time, such as sorting by a chosen field. The standard library's std::invoke and std::mem_fn are built on it.

Takeaways

  • p->m is (*p).m. this is a pointer to the current object.
  • Match new/delete and new[]/delete[], exactly once.
  • Polymorphism needs a pointer or reference, virtual methods and a virtual destructor.
  • Member pointers are applied with .* or ->*.
Try it yourself

Remove the word virtual from speak() in Animal (and remove override from Dog, which would no longer compile). Run again: what does animal->speak() print now?
