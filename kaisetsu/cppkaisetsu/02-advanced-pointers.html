Advanced Pointers

Four tools built on top of the basics: using const to control what may change, moving through an array with pointer arithmetic, pointers that point to other pointers, and pointers to functions used as callbacks.

What the programmer wants you to learn

  • Where you place const decides whether the pointer or the target is read-only.
  • Pointer arithmetic moves through an array element by element, and must stay inside the array.
  • A pointer to a pointer (int**) can change where another pointer points.
  • Functions have addresses too, so you can pass a function to another function as a callback.

<cstddef> is included for std::size_t (an unsigned integer type used for sizes and indexes) and std::ptrdiff_t (a signed type for the distance between two pointers).

Setting up a callback

The top of the file prepares for Section 4. Read it now and come back to it later.

  • print_number is an ordinary function that takes an int.
  • using Callback = void (*)(int); creates a short name (an alias) for the type "pointer to a function that takes an int and returns void". Function-pointer types are hard to read, so an alias helps a lot.
  • process receives an array (as a pointer to its first element plus a count) and a callback. It calls the callback once for every element. It does not know or care what the callback does.

Note const int* values: process promises it will only read the array. The comment on line 13 states the contract: the caller must give a pointer to at least count elements. A raw pointer cannot tell how big the array really is, so the function has to trust the caller.

OOP connection

This is the C++ equivalent of passing a strategy object, a Consumer<Integer> in Java, or a function in Python/JavaScript: process handles the looping, the caller decides what happens to each item.

Section 1: const and pointers

A pointer involves two things that could change: the pointer itself (which address it holds) and the target (the value at that address). const can lock either one, or both.

Trick: read the type right to left

const int* p → "p is a pointer to an int that is const".
int* const p → "p is a const pointer to an int".
Whatever const sits next to (the int or the *) is what is locked.

The commented-out lines 28 and 31 show what the compiler would reject. Try removing the // to see the error messages.

The final comment (lines 36–37) is an important subtlety: const int* only says "you cannot modify it through this pointer". second itself is an ordinary variable and can still be changed by its own name or by another non-const pointer, as happens in Section 3.

Section 2: Pointer arithmetic and arrays

Counting the elements

sizeof(numbers) is the size of the whole array in bytes (4 ints × 4 bytes = 16) and sizeof(numbers[0]) is the size of one element (4). Dividing gives the element count, 4. constexpr means the value is computed at compile time.

Moving a cursor

int* cursor = numbers; works because an array name automatically converts to a pointer to its first element. Adding 1 to an int* moves it to the next int, not the next byte: the compiler multiplies by the element size for you.

[0]3numbers + 0
[1]6numbers + 1
[2]9numbers + 2
[3]12numbers + 3
one past?end

After ++cursor the cursor sits on [1] (value 6). end is a valid address, but there is no element there.

The end pointer is "one past the last element". C++ lets you form that address and compare or subtract with it, but you must never dereference it. end - cursor gives the distance in elements (4, because the cursor was moved back to index 0).

numbers[i] is *(numbers + i)

The loop prints each element in two ways to prove they are the same. Square-bracket indexing is really just pointer arithmetic plus a dereference.

Stay inside the array

Unlike Java or Python, C++ does not check array bounds. numbers[10] compiles and silently reads whatever memory is there. Lines 54–56 list the rules: an array is not a pointer (so sizeof sees the whole array), arithmetic must stay within the array or one past it, and you may only subtract pointers into the same array.

Section 3: Pointers to pointers

A pointer is a variable, so it also has an address. int** is "a pointer to a pointer to an int".

pointer_to_pointer&targetint**
target&firstint*
first42int
  • One star *pointer_to_pointer reaches target (the middle box). Assigning to it re-targets target.
  • Two stars **pointer_to_pointer goes all the way to the int at the end.

So line 64 sets first to 42. Line 66 makes target point to second instead, and line 67 sets second to 84, even though second was earlier reached through a const int*. This is the "mutable alias" mentioned in Section 1.

Where is this used? Mostly when a function needs to change which object the caller's pointer points to, or for arrays of pointers (such as char** argv in main).

Section 4: Function pointers and callbacks

void (*function_pointer)(int) declares a variable named function_pointer that can hold the address of any function taking an int and returning void. The parentheses around *function_pointer are required; without them it would declare a function returning void*.

  1. function_pointer(7) calls print_number through the pointer.
  2. The same address is copied into a variable of the friendlier Callback type.
  3. process(numbers, count, callback) calls the callback for each of the four numbers.
  4. process(numbers, count, nullptr) shows the safety check: with no callback, it just returns.
What about lambdas?

The last comment mentions that a lambda which captures variables (for example [&total](int v) { total += v; }) cannot be stored in a plain function pointer. For those, modern C++ uses std::function<void(int)>, which can hold any callable object.

Takeaways

  • const left of * locks the target; right of * locks the pointer.
  • p + 1 moves by one element. Keep arithmetic inside the array (or one past it).
  • Each * follows one arrow. **pp follows two.
  • Function pointers let you pass behavior into reusable code.
Try it yourself

Write a second callback, void print_double(int value), that prints value * 2, and pass it to process. Nothing inside process needs to change.
