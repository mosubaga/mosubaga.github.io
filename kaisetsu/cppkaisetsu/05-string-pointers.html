What the programmer wants you to learn

  • A std::string* holds the address of a whole string object.
  • Use * to work with the whole string and -> to call its methods.
  • Pass a string to a function by pointer so it can modify it.
  • Use const std::string* for read-only access, and handle nullptr.

Compare this file with Lesson 01: the structure is almost identical, with int replaced by std::string.

The helper function

Like change_target in Lesson 01, this function receives an address, checks for nullptr, and then modifies the caller's object. Because text is a pointer to an object, it calls the method with text->append(...).

Section 1: Pointing to a std::string

"The pointer points to the string object, not directly to its characters."

The comment on lines 18–19 makes a precise point. A std::string is an object that manages its characters internally (its length, its buffer, and so on). text_pointer points at that whole object. *text_pointer is therefore the complete string, which is why cout prints Hello.

A classic trap: text_pointer[0]

Remember from Lesson 02 that p[i] means *(p + i). So text_pointer[0] is the whole string (the first element of a pretend array of strings), not its first character. To index the characters, dereference first: (*text_pointer)[0]. The parentheses are necessary.

Section 3: Reassigning a string pointer

Just as in Lesson 01, giving the pointer a new address changes which string it refers to. += then appends to message, and greeting is untouched.

Section 4: Passing a pointer to a function

append_message(&message) passes the address, so the function modifies the real message. Calling it with nullptr is handled safely by the check inside the function.

Pointer or reference?

The final takeaway says: "Prefer a reference parameter when a string must be supplied." A reference (std::string& text) can never be null, so the check disappears and calls look simpler:

Use a pointer when "no object" is a valid input; use a reference when an object is required.

Section 5: Read-only access and nullptr

const std::string* read_only is a "pointer to a const string" (see the const table in Lesson 02). You may read through it and call const methods such as size(), but not modifying ones such as append(); line 48 would not compile. The pointer itself is not const, so line 50 can point it at greeting.

Finally the pointer is set to nullptr and checked before any use.

Lifetime and c_str()

Two closing warnings:

  • Borrowed pointers. Both strings are local variables; the pointers merely borrow them. Never delete them, and never keep their addresses after the strings go out of scope.
  • std::string* is not const char*. In C, a "string" is a char array, handled through a const char* pointing at the first character. A std::string can give you such a pointer with c_str(), but that points into the string's internal buffer. If the string later grows, it may move its characters to a new buffer, and the old c_str() pointer becomes invalid.

Takeaways

  • std::string* points to a string object: *p is the string, p->method() calls its methods.
  • Index characters with (*p)[i], not p[i].
  • Check nullable pointers, and keep their targets alive.
  • If an argument is required, a reference parameter is usually the better choice.
Try it yourself

Write void shout(std::string* text) that appends "!!!" and converts the first character to upper case with (*text)[0] = std::toupper((*text)[0]); (include <cctype>). Remember the null check, and that the string must not be empty before indexing.
