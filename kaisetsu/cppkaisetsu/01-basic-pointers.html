Lesson 01 Beginner

Basic Pointers

Your first look at memory addresses. This program shows how to get an address with &, store it in a pointer, use * to reach the value at that address, and why passing an address to a function is different from passing a value.

What the programmer wants you to learn

The first comment in the file states the goal:

  • Every variable has an address, and & gives it to you.
  • A pointer must be initialized, and nullptr means "points nowhere".
  • *pointer dereferences: it reads or writes the variable being pointed to.
  • A pointer can be reassigned to point somewhere else.
  • Passing a value gives a function a copy; passing an address lets it change the original.

The program is split into five numbered sections, each printing a heading like === Section 1 ... ===, so you can match the output to the code.

The two helper functions

Before main(), the program defines two functions that both try to set a number to 99. They are used in Section 5, but reading them first makes the ending easier to follow.

  • change_copy(int value) receives an int. C++ copies the argument into the parameter, so value = 99 only changes the function's private copy.
  • change_target(int* value) receives a pointer to an int, that is, an address. *value = 99 writes 99 at that address, which changes the caller's variable.
Why the nullptr check?

As the comment on line 11 says, someone could call change_target(nullptr). Dereferencing a null pointer is undefined behavior: usually a crash, but the language makes no promises. A function that accepts a pointer should check it before using *.

Section 1: Variables and addresses

Two ordinary int variables are created. Writing &apples means "the address of apples". When you print an address with std::cout, you get a hexadecimal number such as 0x16ee6e15c.

Your numbers will be different

The comment on line 25 warns that addresses change every time you run the program (operating systems deliberately randomize them). The idea matters, not the specific number.

Syntax notes: std::cout << x prints x, and '\n' is a newline character. std:: means the name comes from the C++ standard library.

Section 2: Declaration and initialization

int* fruit_pointer declares a variable whose type is "pointer to int". It can only hold addresses of int variables. It starts as nullptr on purpose: the comment says "Never leave a pointer uninitialized." An uninitialized pointer holds a random leftover address, and using it could corrupt any part of memory.

Then fruit_pointer = &apples; stores the address of apples in the pointer. The programmer drew a small diagram in the comment on lines 33–36. Here it is as a picture:

Notice that the pointer's value is exactly the address of apples printed in Section 1.

Section 3: Reading and writing through a pointer

Putting * in front of a pointer dereferences it: "go to the address stored in the pointer and use what is there."

  • *fruit_pointer on the right side reads apples → 10.
  • *fruit_pointer = 15; writes to apples. We never mentioned apples by name, yet it changed to 15.
OOP connection

This is like two Java variables referring to the same object: modify it through one name, and the other name sees the change. Here apples and *fruit_pointer are two names for the same int.

Section 4: Reassigning the pointer

Assigning to the pointer itself (no *) changes which variable it points to. As the comment says, this "changes the address, not the previous target": apples keeps its value 15. The following write *fruit_pointer = 25 now goes to oranges.

Borrowed, not owned

Lines 47–48 warn that these pointers only borrow local variables. You must not delete them (they were not created with new), and you must not return their addresses from a function: local variables are destroyed when the function ends, leaving a dangling pointer.

Section 5: Value versus pointer parameters

Now the helper functions from the top of the file are put to work:

  1. change_copy(apples): the function receives a copy of 15, sets the copy to 99, prints 99, then the copy disappears. apples is still 15.
  2. change_target(&apples): the function receives the address of apples and writes 99 there. apples becomes 99.
  3. change_target(nullptr): the null check catches it and prints a message instead of crashing.
  4. Finally the pointer is reset to nullptr so it is clearly marked "no target".
The pointer itself is still copied

The closing comment points out a subtle detail: "A pointer parameter is itself copied, but can modify the pointee." change_target gets its own copy of the address. Both copies point to the same apples, which is why the change is visible outside.

Takeaways

  • &x gets an address; *p accesses the target.
  • p = &y changes where the pointer points, not the old target.
  • Pass an address when a function must modify the caller's variable.
  • Check for nullptr, and make sure the target is still alive whenever you use the pointer.
Try it yourself

Add std::cout << *fruit_pointer; after line 56. The program now dereferences nullptr. Run it and see what happens, then remove the line again.
